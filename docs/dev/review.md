# レビューと完了条件

成果物（設計書・実装・調査レポート・Skill・設定ファイルなど）を作成・更新したときに従うルール。軽微な変更でも必ずレビューを経てから完了とする。

## レビュー

- レビューには既存の手段（Superpowers のレビュー系スキルなど）を使う。レビューのためだけに新しい Skill は作らない
- レビューは可能な限り別セッション・別エージェントで、作成者とは別の観点から行う。難しい場合も、作成者視点と切り離したセルフレビューを行う
- 指摘は成果物を作成したセッションで修正し、完了条件に関わる指摘が解消されるまでレビューと修正を繰り返す
- 指摘から得た知見は、同じ指摘を繰り返さないよう `docs/dev/`・AGENTS.md・Skill に蓄積する（`docs/spec/` の仕様書には原則書かない）

## 完了条件

- 変更に合わせてテストとドキュメントを更新する
- 完了報告には次を含める：変更内容、検証結果（実行したテストとその結果。未実行ならその旨）、レビュー状況（レビュー方法と未解消の指摘）、残課題
